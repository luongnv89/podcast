Bob: Attention is how a token decides which earlier tokens matter for the next prediction. Picture a noisy party: through all the chatter, your ear snaps to the one voice saying your name. In the model, attention picks out the earlier tokens that matter right now.

Bob: And attention is one reason local models are so hungry for memory, Ahmad says. Classic multi-head attention keeps separate key and value state for many heads, which makes the KV cache large, while newer designs like GQA share key and value heads across groups.

Alice: So two models of the same size can behave differently?

Bob: Very differently! A 7B model with classic attention at 128K context can exhaust a GPU with 24 gigabytes, while a 7B GQA model may fit with room to spare. Parameter count isn't the whole story.

Alice: You keep saying KV cache. What is it, really?

Bob: It's the model's working memory during generation. It stores the key and value states of earlier tokens, so the model doesn't recompute the whole history for every new token.

Alice: Metaphor, please. I'm the beginner today.

Bob: Imagine a waiter at a big table: without a notepad, he'd make everyone repeat the whole order each time he added one dish. The KV cache is that notepad: earlier tokens are already written down, so without it, generation would be brutally inefficient.

Alice: But notepads fill up.

Bob: Exactly, and that's the bill. For older Llama-like 7B models, his rule of thumb is about half a megabyte per token, so 4K tokens can cost around 2 gigabytes just for the cache. At 32K tokens, you may be looking at 16 gigabytes of cache alone.

Alice: Sixteen just to remember the chat? Ouch!

Bob: Ouch indeed. That's why a model can fit with an empty prompt but crash when you load a long document. The weights fit, the working memory did not.

Alice: Back to our teaser. Why the pause, then the slow typing?

Bob: Two phases! Prefill processes your prompt: paste a 20,000-token document, and the model must process all of it before the first answer token. Then decode generates new tokens one at a time, and that's the streaming typing effect.

Alice: Okay, make it kitchen-simple.

Bob: Think of an exam: you take in the whole question first, then you write your answer in pen, word by word, each word depending on the one before. Reading is prefill, which runs in parallel; writing is decode, which is sequential.

Alice: So which one hurts more?

Bob: Long prompts punish prefill, long answers punish decode, and long conversations punish both, because the KV cache grows.

Alice: That's why endless chats get sluggish?

Bob: Right. Let a chat run to 16K tokens, and you pay the memory cost for all of them on every new token. That's why chat apps that keep infinite history eventually slow down or crash.

Alice: And how does it pick each token? Highest score every time?

Bob: That's one option. The model only scores every possible next token; decoding turns those scores into one actual token. It can take the top one, sample from a narrowed set of likely ones, penalize repetition, or stop at a delimiter.

Alice: And temperature is the famous knob?
